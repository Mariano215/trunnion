# Proof 24, one screen that cannot flatter the ledger behind it

## 1. The claim

Trunnion had nine views and each answered one question. None answered "is this
harness healthy right now", which is the question an operator opens a console
to ask and the question a reviewer asks first in a briefing.

The shape this slice copies is a single pane built for an Air Force brief: tiles
across the top, a live run stream, a control topology, a twelve-primitive grid.
That console carried a banner reading `SYNTHETIC DEMONSTRATION DATA // NO
OPERATIONAL SYSTEM CONNECTED`, because nothing was feeding it. Every number on
it exists in this ledger already, including two that had never been surfaced:
`duration_ms` on `tool.result` and `latency_ms` on `model.call` have been
emitted since slice 04 and slice 10 and no view has ever read them.

So the claim is not that the screen can be drawn. It is that the screen can be
drawn **without ever printing a number the log does not support**, which is the
thing a dashboard is structurally tempted to do.

## 2. The adversarial case

A dashboard's failure mode is not a wrong number, it is a confident number. The
three attacks all take the same shape: make the view say more than the record
does.

**(a) Absent rendered as zero.** A ledger that has never carried an `approval`
and a ledger whose approvals all fell outside the window are different states.
Rendering both as `0` next to the caption "named authority on each" tells a
reviewer that a human gate was exercised and came back clean, when in the first
case it was never instrumented at all. The aggregate returns null for a kind the
log has never carried and a number for one it has, and the front end renders
null through `num()` as a dash with a note naming which state it is.

**(b) A percentile over almost nothing.** `p95` over four samples names one
sample and dresses it as a distribution. Under `LATENCY_SAMPLE_FLOOR` the
percentile is null and `samples` travels with it either way.

The first version of the tile failed this in the opposite direction, and the
render caught it: the note read "no telemetry on this ledger" over four real
measurements, because a helper clobbered the caller's note whenever the value
was null. Absent and thin are both null and are not the same statement. The note
is now a parameter, and the thin case reads `4 samples, 20 needed for a
percentile`.

**(c) An arrow that asserts a handoff.** The brief's topology is a flow diagram.
`tests/invariants.rs` has held since slice 21 that the trace view derives no
edge from an event kind alone, because an edge asserts a handoff and only a
producer recording a peer may assert one. A second diagram drawn in the same ink
from the same log would quietly reintroduce exactly that inference.

The resolution is that the two pictures answer different questions and say so.
The trace view draws observed handoffs and prints `inferred: 0`. The operations
topology draws declared architecture, prints `9 edges declared by layout · 0
derived from the record`, and carries a caption telling the reader that an arrow
there asserts nothing about the log. Only the per-node counts are read from it.

## 3. The evidence

Built by running it, against a ledger the binary produced.

### 3.1 The aggregate is a route, not browser arithmetic

`/api/events` answers at most 1000 rows. A front end counting denials or taking
a percentile over that page would be describing the page while the tiles read as
a statement about the whole log, which is the failure `CLAUDE.md` already names
for a browser-side filter count. `GET /api/operations` computes over the whole
ledger and is documented in `docs/CONSOLE-API.md`.

Against a fresh ledger with two broker calls, one of them refused:

```
"denials":   {"count": 1,    "source": "policy.decision where verdict is deny"}
"holds":     {"count": 0,    "source": "policy.decision where verdict is hold"}
"approvals": {"count": null, "source": "approval"}
```

Zero and null side by side in one response, meaning different things.

### 3.2 The window is a claim about now

The boundary is measured against the request time, not the newest row, so a
ledger nobody has written to today reports zero rather than its lifetime totals
under a "24h" label. `the_window_is_a_claim_about_now_so_an_old_ledger_reports_zero_and_not_its_totals`
drives the slice 10 fixture, dated 2026-08-05, and asserts `scanned: 0` with
`denials: 0` rather than null, because the kind is on the log.

An unreadable window is refused rather than defaulted:
`a_window_this_route_does_not_read_is_refused_rather_than_quietly_defaulted`
asserts 400 and a fix naming the three valid values.

### 3.3 The percentile floor

`a_percentile_under_the_sample_floor_is_null_and_the_sample_count_travels_with_it`
builds two ledgers, four `tool.result` events and twenty, with a spread of
durations so a percentile that returned the mean or the first sample would
differ from the one asserted. At four: `p50` and `p95` null, `samples` 4, `max`
30. At twenty: `p50` 90, `p95` 180 by nearest rank.

### 3.4 Rendered, and asserted against the ledger

`ci/console-render.sh` renders `#/operations` in headless Chrome with the other
eight views and asserts tile values read off the fixture at check time rather
than written into the script: the `run.open` count, the head size, and the deny
count. It asserts the absent branch through the topology (`>no telemetry<` on a
node whose kinds the fixture never produced) and the thin branch through the
p95 note. It asserts `0 derived from the record` is on screen.

Proved able to fail: changing one `TOPO_EDGES` endpoint from `'gateway'` to
`'tool.request'` fails
`the_operations_topology_declares_its_edges_and_derives_none_from_an_event_kind`
with "edge endpoint \"tool.request\" looks like an event kind". Restored and
re-run clean.

### 3.5 A build gotcha worth recording

The console's assets are `include_str!`'d into the binary. Editing
`assets/views.js` and re-serving renders the old view, silently, because the
running binary carries the previous text. The first two rounds of visual
checking here were against stale assets and looked like the fixes had not
worked. `cargo build` is part of changing a view, not part of shipping one.

## 4. What surprised you

Pointing the workspace view at ClaudePaw, the most agentic project on this
machine, scored primitive 10 Verification at 0: "looked in tests/, test/, spec/,
__tests__/, src/test/: found nothing". ClaudePaw declares `"test": "vitest run"`
in `package.json` and carries hundreds of colocated `*.test.ts` files.

That is issue #1 reproducing on a real repository rather than in the abstract.
The probes encode a directory convention that TypeScript projects mostly do not
follow, and the scan reports the honest thing about where it looked while
reaching the wrong conclusion about the repository. The scan is the growth
engine, per `docs/CLAUDE-CODE-INTEGRATION.md`, so it is the surface where being
wrong costs the most.

Nothing in this slice changes it. It is recorded here because this slice is what
put a real project in front of it.

## 5. Conformance delta

No primitive moves. This slice adds no control and enforces nothing new; it
reads what the ledger already carries. Claiming a score change for a view would
be the scoring defect proof 13 records, where the way to raise a number was to
change what a rule keyed on.

Two fields reach an operator surface for the first time: `tool.result.duration_ms`
and `model.call.latency_ms`, emitted since slices 04 and 10 and read by nothing
until now.

## 6. What is still a guide

- **The tiles are thin on a laptop.** Every number here is real, and on a ledger
  of thirty events they are small. The brief's console showed 1,249 runs and
  9,580 records because nothing was connected. Making these numbers large means
  connecting a real harness, not generating one.
- **Nothing feeds the ledger from a real coding session.** `trunnion up` is
  still not built and the only hook shipped is `permission-mode.sh`, which
  injects a variable and writes no events. Until the pre-tool and session hooks
  exist, the operations view describes ledgers made by proof scripts and by hand.
  ClaudePaw is the obvious first client and cannot be one yet.
- **`window` is three fixed values.** An arbitrary range would need a parser and
  a decision about what an open-ended window means for a percentile.
- **The topology's node table lives in `src/console.rs` and its layout in
  `assets/views.js`.** They agree by review. A node added to one and not the
  other renders as absent, which is safe but silent, and no check ties them.
